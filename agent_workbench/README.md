# Agent Workbench

`agent_workbench/` is the automation control plane for this STM32 UART CLI project. It stays frontend-neutral: the core CLI handles build, flash, UART, diagnostics, planning, verification, and evidence capture, while editor or AI-specific assets live in `integrations/`.

## Quick Start

```powershell
cd H:\stm32_RAG\code\serial
agent_workbench\bin\setup.bat
cmd /c ".\agent_workbench.bat doctor --json"
cmd /c ".\agent_workbench.bat init-vscode --json"
cmd /c ".\agent_workbench.bat integration list --json"
```

For this repository, the current defaults are:

- project: `serial`
- build dir: `build/cmake-debug`
- UART CLI: `COM3 / 115200`
- ready banner: `STM32 UART CLI ready.`
- prompt: `cli>`

The single source of truth is [agent_workbench.yaml](agent_workbench.yaml).

## Main Commands

```powershell
cmd /c ".\agent_workbench.bat doctor --json"
cmd /c ".\agent_workbench.bat build --json"
cmd /c ".\agent_workbench.bat flash --method openocd_cmd --json"
cmd /c ".\agent_workbench.bat reset --method openocd_cmd --json"
cmd /c ".\agent_workbench.bat scan-project --json"
cmd /c ".\agent_workbench.bat plan ""add PWM output on PA8, 1kHz, 50% duty"" --json"
cmd /c ".\agent_workbench.bat verify current --task agent_workbench/tasks/cli_automation_regression.yaml --json"
cmd /c ".\agent_workbench.bat test run --json"
cmd /c ".\agent_workbench.bat report --latest --json"
```

## Integrations

The core CLI and integrations are deliberately separate.

- Core commands live in `workbench.py` and `core/`.
- AI/editor packs live in `integrations/<name>/`.
- Each integration is self-contained: `manifest.yaml`, `files/`, and `README_ZH.md`.

Built-in integrations in this repo:

- `opencode`
- `continue`

Use them through the unified `integration` command:

```powershell
cmd /c ".\agent_workbench.bat integration list --json"
cmd /c ".\agent_workbench.bat integration install opencode --json"
cmd /c ".\agent_workbench.bat integration install continue --json"
cmd /c ".\agent_workbench.bat integration check opencode --json"
cmd /c ".\agent_workbench.bat integration remove continue --json"
```

Compatibility shims remain available:

- `init-opencode-agents` -> `integration install opencode`
- `init-continue-rules` -> `integration install continue`

## Local-Model Workflow

The low-context workflow still uses staged artifacts generated by `context`:

- `*_brief.md`
- `*_facts.json`
- `*_constraints.json`
- `*_resume.md`
- `*_paste.md`
- `agent_state.json`

Profiles are configured under `agent.default_profile` and `agent.profiles` in [agent_workbench.yaml](agent_workbench.yaml).

## Evidence-First Workflow

For debug and feature work, conclusions should come from generated evidence rather than source inspection alone.

Primary artifacts include:

- `agent_workbench/runtime/direct_verify_summary.md`
- `agent_workbench/runtime/direct_verify_summary.json`
- `cli_transcript.log`
- `cli_diag.json`
- `diag_exchange.log`
- `diag_exec_result.json`
- `session_summary.md`
- `feature_summary.md`
- `compare_vs_*.md`

## Repo Layout

- `core/`: Python implementation
- `integrations/`: pluggable AI/editor packs
- `templates/`: planner templates and build rules
- `tasks/`: task specs for verify/session/test flows
- `generated/`: generated task artifacts
- `evidence/`: session evidence
- `runtime/`: latest logs and transient outputs

## Notes

- `uart console` still works best with `pyserial`.
- If `pyserial` is unavailable, the PowerShell fallback still supports `uart exec`, `diag exec`, and logging flows.
- If your USB-TTL adapter is not on `COM3`, update both `uart.port` and `diag_uart.port` in [agent_workbench.yaml](agent_workbench.yaml) before running hardware sessions.
