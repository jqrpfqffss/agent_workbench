# 测试失败分层

改代码前先分层。

## 1. 测试设计问题

表现：

- 预期行为模糊
- probe 不匹配用户目标
- 断言目标是不稳定字符串或数值

动作：先修覆盖矩阵、probe 命令或断言目标。

## 2. Probe 或可观测性问题

表现：

- `uart exec` 没有发送能触发功能的命令
- `diag exec` 请求不匹配当前协议
- `monitor probe` 读取了错误或不存在的符号

动作：先修命令、请求、monitor 项或可观测路径。

## 3. 源码行为问题

表现：

- 测试设计清楚
- probe 确实触发行为
- runtime evidence 证明行为不符合预期

动作：修改生产代码，然后重新 build 并重跑 runtime evidence 路径。

## 4. 环境或硬件阻塞

表现：

- `doctor` 失败
- `flash` 失败
- UART 无接收字节
- monitor 无法采样

动作：停止并报告阻塞，不把它写成固件测试失败。

## 决策顺序

依次确认：

1. 测试设计是否正确？
2. probe 是否触发行为？
3. runtime evidence 是否可用？
4. 源码行为是否真的违反预期？
