# 测试覆盖矩阵

为复杂功能或回归工作设计验证时，使用此矩阵审查覆盖强度。

## 矩阵字段

每个关键行为都应映射到：

- 行为
- 刺激
- 期望证据
- 断言类型
- 证据来源
- 失败层
- 是否需要硬件
- 回归相关性

## 模板

```markdown
| 行为 | 刺激 | 期望证据 | 断言 | 来源 | 失败层 | 需要硬件 | 回归 |
|---|---|---|---|---|---|---|---|
| <behavior> | <CLI/diag/event> | <ack/status/value> | <assertion type> | <artifact> | <layer> | <yes/no> | <yes/no> |
```

## 最小覆盖

### CLI 命令

- help 或命令列表中能看到命令。
- 正常命令返回稳定响应。
- 缺失或非法参数后 prompt 能恢复。
- 修改共享 parser 时，核心命令仍可用。

### 外设功能

- build 通过。
- 初始化路径被执行。
- 控制或触发路径被执行。
- 运行态通过 CLI、diag 或 monitor 可见。
- 实机验证已运行，或明确被环境阻塞。

### 调试回归

- 失败症状已复现，或明确不可复现。
- 有 baseline 或历史 evidence 时进行对比。
- 已识别失败层。
- 记录下一条最小实验。

### 协议或 diag

- request 格式来自当前项目定义。
- response shape 有断言。
- 必要时覆盖 timeout 或 malformed response。

## 质量门槛

弱验证计划：

- 只检查 build 成功。
- 只检查 `help`，没有目标行为。
- 断言字符串不来自配置、runtime evidence 或明确行为契约。
- 不能区分环境失败和源码行为失败。
- 硬件相关行为没有 CLI、diag 或 monitor 证据路径。

强验证计划：

- 每个关键行为至少有一个证据来源。
- 断言单一、可诊断。
- 明确真实硬件需求。
- 修改共享代码时覆盖回归风险。
- 最终报告列出 artifact。
