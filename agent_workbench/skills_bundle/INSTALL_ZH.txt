将本目录下的 skill 文件夹复制到 OpenCode/Codex 可识别的 skills 目录即可使用。

推荐位置：

1. 如果设置了 `CODEX_HOME`：
   `%CODEX_HOME%\skills\`

2. 如果没有设置 `CODEX_HOME`：
   `%USERPROFILE%\.codex\skills\`

安装后应直接看到这些目录：

英文版：

- `agent-workbench-toolbox`
- `agent-workbench-feature`
- `agent-workbench-debug`
- `agent-workbench-test`

中文版：

- `agent-workbench-toolbox-zh`
- `agent-workbench-feature-zh`
- `agent-workbench-debug-zh`
- `agent-workbench-test-zh`

推荐做法：

1. 关闭当前 Codex / Continue / OpenCode 会话。
2. 将上述目录复制到 `skills` 目录。
3. 重新打开会话。
4. 在任务里明确提到对应 skill 名称，或直接描述功能开发、自动调试、测试设计与实机验证意图。

推荐组合：

- 英文功能开发：`agent-workbench-toolbox` + `agent-workbench-feature`
- 英文自动调试：`agent-workbench-toolbox` + `agent-workbench-debug`
- 英文测试设计与验证：`agent-workbench-toolbox` + `agent-workbench-test`
- 中文功能开发：`agent-workbench-toolbox-zh` + `agent-workbench-feature-zh`
- 中文自动调试：`agent-workbench-toolbox-zh` + `agent-workbench-debug-zh`
- 中文测试设计与验证：`agent-workbench-toolbox-zh` + `agent-workbench-test-zh`

核心特性：

- 使用稳定 PowerShell 调用：`.\agent_workbench\bin\agent_workbench.bat <command> --json`
- bat 入口失败时使用 direct Python 兜底：`python ".\agent_workbench\workbench.py" <command> --json`
- 优先读取 JSON 和 evidence artifacts。
- 使用 runtime evidence、UART/diag/monitor、verify/report/compare 作为功能开发、自动调试和测试验证闭环。
- monitor 变量、寄存器、地址由 OpenCode 自动检查并编辑 `agent_workbench/agent_workbench.yaml`。
- 提供功能开发、自动调试、测试设计与实机验证的方法论。
- 提供三类稳定报告模板：功能开发报告、调试报告、测试验证报告。
- 不绑定具体工程路径、串口号、ready banner、prompt、源码目录或 MCU 地址；这些信息必须由 `doctor`、`scan-project`、当前源码和 runtime evidence 动态获得。
