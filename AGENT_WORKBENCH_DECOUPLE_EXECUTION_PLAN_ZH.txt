1.1 当前问题（硬切换遗留的耦合点）

 agent_workbench/core/vscode_service.py
    - 包含 write_opencode_agents() 函数，硬编码 OpenCode 文件列表/路径

    - 包含 _check_opencode_agents()，硬编码 opencode_agents_file 等检查项名
    - _check_migration_docs 要求必须存在 OPENCODE_AUTO_MODE_GUIDE_ZH.md
 agent_workbench/core/config.py
    - _defaults() 返回的 dict 里直接内含 "opencode": {...} 默认段
    - load_config() 里解析 oc = raw.setdefault("opencode", {}) 派生 *_path
 agent_workbench/core/project_scanner.py
    - scan_project() 结果里硬编码 opencode_agents_file / opencode_agents_dir / opencode_commands_dir
 agent_workbench/core/ps_exec.py
    - _KNOWN_COMMANDS 包含 init-opencode-agents
 agent_workbench/workbench.py
    - 有 _cmd_init_opencode_agents 函数和 init-opencode-agents subparser
    - _cmd_scan_project 的 artifacts 里硬编码 opencode_*
 agent_workbench/agent_workbench.yaml
    - 顶层有 opencode: 整段配置
 agent_workbench/templates/opencode_agents/
    - 把前端模板放在 agent_workbench 内部，违反分层
 agent_workbench/tests/test_*.py
    - 测试里嵌入 opencode_* 字段断言

1.2 架构原则（新的边界）

 agent_workbench/ = "前端中立"的硬件/构建自动化工具平台
    核心能力: doctor / build / flash / reset / uart / diag / monitor /
              openocd / plan / fix-build / scan-project / context / verify /
              session / test / report / init-vscode
    绝不包含: 任何 opencode_* / continue_* / cursor_* / cline_* 字样的代码、
              配置段、CLI 子命令

 agent_workbench/integrations/<name>/ = AI 前端集成包（可插拔）
    每个子目录是一个独立、自包含的"贴装包"，含:
      - manifest.yaml  : 声明要生成的文件清单 + doctor 规则
      - files/...      : 模板文件（.tpl 后缀走渲染，否则原样拷贝）
      - README_ZH.md   : 该前端的使用指南（随包）

 新 CLI 命令族: `agent_workbench.bat integration <action> [<name>...]`
    action ∈ {list, install, check, remove}
    对 workbench core 完全通用，不区分前端类型

1.3 可行性结论

 AI 前端配置本质 = "在项目根丢一组文件（含若干变量待渲染）"
 workbench 的核心 CLI 对前端零依赖（输入输出都是 JSON）
 现有硬编码逻辑都可机械化抽成通用的 "render manifest + check manifest"
 未来新增 cursor / cline / 公司自定义前端 = 加一个子目录，零 Python 改动

3. manifest.yaml 规范（非常重要，新模型必须严格遵守）
================================================================================

3.1 必需字段

    id: opencode                         # 唯一 ID，对应目录名
    display_name: OpenCode               # 人类可读名
    description: 一句话描述

    files:                               # 文件清单（有序）
      - src: <path relative to files/>
        dst: <path relative to project_root>
        render: true|false               # 可选，默认 true；false 表示原样拷贝
      - ...

3.2 可选字段

    uses_values:                         # 声明本集成用到哪些模板变量（仅文档）
      - project_name
      - ready_banner
      - prompt
      - uart_port
      - diag_uart_port
      - build_dir
      - default_profile
      - source_dirs_csv

    doctor:
      required_files:                    # doctor 会检查这些路径是否存在
        - AGENTS.md
        - .opencode/agent/stm32_auto.md
      markers:                           # 对某些已生成文件做关键字校验
        AGENTS.md:
          - "{project_name}"
          - "{ready_banner}"
          - "{prompt}"

3.3 变量字典（统一由 integrations_service._render_values(cfg) 派生）

    project_name      <- cfg["project"]["name"]
    ready_banner      <- cfg["uart"]["ready_banner"]
    prompt            <- cfg["uart"]["prompt"]
    uart_port         <- cfg["uart"]["port"]
    uart_baud         <- cfg["uart"]["baudrate"]
    diag_uart_port    <- cfg["diag_uart"]["port"]
    build_dir         <- cfg["project"]["build_dir_path"]
    default_profile   <- cfg["agent"]["default_profile"]
    source_dirs_csv   <- ", ".join(cfg["project"]["source_dirs"])

3.4 模板语法

    和 core/utils.py::render_template 一致：{key} 原样替换。
    不支持 {% if %} / {{ }} 等其他模板引擎。保持简单。

5. 新 CLI 命令规范（workbench.py 新增）
================================================================================

5.1 subcommand 签名

agent_workbench.bat integration list [--json]
    列出所有可发现的集成包。输出 JSON 字段:
      command: "integration list"
      details.integrations: [
        {id, display_name, description, installed: bool, pack_dir},
        ...
      ]
    installed 判断: manifest.doctor.required_files 全部存在即认为已装

agent_workbench.bat integration install <id> [<id2> ...] [--config ...] [--json]
    依次调用 install_integration。输出:
      details.installed: [id1, id2, ...]
      artifacts.files: [path list]

agent_workbench.bat integration check <id> [--json]
    输出:
      details.results: [...]   # check_integration 返回
      exit_code = 0 if 全 ok else 1

agent_workbench.bat integration remove <id> [--json]
    输出:
      details.removed: [id]
      artifacts.files: [path list 已删]

import tempfile, unittest, shutil, yaml
from pathlib import Path
from agent_workbench.core import integrations_service


class IntegrationsServiceTests(unittest.TestCase):
    def setUp(self):
        self.tmp = Path(tempfile.mkdtemp(prefix="awb_integ_"))
        self.workbench_root = self.tmp / "agent_workbench"
        self.project_root = self.tmp / "project"
        self.project_root.mkdir(parents=True)
        pack_dir = self.workbench_root / "integrations" / "dummy"
        (pack_dir / "files").mkdir(parents=True)
        # 写 manifest + 一个模板文件
        (pack_dir / "manifest.yaml").write_text(
            "id: dummy\n"
            "display_name: Dummy\n"
            "description: test pack\n"
            "files:\n"
            "  - src: hello.md.tpl\n"
            "    dst: hello.md\n"
            "uses_values: [project_name]\n"
            "doctor:\n"
            "  required_files:\n"
            "    - hello.md\n"
            "  markers:\n"
            "    hello.md:\n"
            '      - "{project_name}"\n',
            encoding="utf-8",
        )
        (pack_dir / "files" / "hello.md.tpl").write_text(
            "project is {project_name}\n", encoding="utf-8"
        )
        self.cfg = {
            "project_root_path": self.project_root,
            "agent_workbench_root_path": self.workbench_root,
            "project": {"name": "demo_proj", "source_dirs": [], "build_dir_path": self.tmp/"build"},
            "uart": {"ready_banner": "R", "prompt": "P", "port": "COM3", "baudrate": 115200},
            "diag_uart": {"port": "COM4"},
            "agent": {"default_profile": "balanced_local"},
        }

    def tearDown(self):
        shutil.rmtree(self.tmp, ignore_errors=True)

    def test_discover_integrations_finds_manifest_subdirs(self):
        ms = integrations_service.discover_integrations(self.workbench_root)
        ids = [m.id for m in ms]
        self.assertIn("dummy", ids)

    def test_install_integration_writes_expected_files_with_rendered_values(self):
        [m] = integrations_service.discover_integrations(self.workbench_root)
        written = integrations_service.install_integration(self.cfg, m)
        hello = self.project_root / "hello.md"
        self.assertIn(hello, written)
        self.assertEqual((hello).read_text(encoding="utf-8"), "project is demo_proj\n")

    def test_install_integration_rejects_path_traversal(self):
        pack_dir = self.workbench_root / "integrations" / "evil"
        (pack_dir / "files").mkdir(parents=True)
        (pack_dir / "manifest.yaml").write_text(
            "id: evil\n"
            "display_name: Evil\n"
            "description: x\n"
            "files:\n"
            "  - src: x.tpl\n"
            "    dst: ../outside.md\n"
            "doctor: {required_files: [], markers: {}}\n",
            encoding="utf-8",
        )
        (pack_dir / "files" / "x.tpl").write_text("x\n", encoding="utf-8")
        [m] = [x for x in integrations_service.discover_integrations(self.workbench_root) if x.id == "evil"]
        with self.assertRaises(RuntimeError):
            integrations_service.install_integration(self.cfg, m)

    def test_check_integration_reports_missing_files_as_warn(self):
        [m] = [x for x in integrations_service.discover_integrations(self.workbench_root) if x.id == "dummy"]
        results = integrations_service.check_integration(self.cfg, m)
        # 没装呢，hello.md 不存在，应该有 warn
        levels = [r["level"] for r in results]
        self.assertIn("warn", levels)

    def test_remove_integration_deletes_only_manifest_files(self):
        [m] = [x for x in integrations_service.discover_integrations(self.workbench_root) if x.id == "dummy"]
        integrations_service.install_integration(self.cfg, m)
        self.assertTrue((self.project_root / "hello.md").exists())
        removed = integrations_service.remove_integration(self.cfg, m)
        self.assertIn(self.project_root / "hello.md", removed)
        self.assertFalse((self.project_root / "hello.md").exists())

10. 附录 B：调试技巧
================================================================================

B.1 PyYAML 找不到？
    用 .\agent_workbench.bat 开头，不要用 `python -m unittest`
    workbench.bat 内部会挑到带 yaml 的 Python

B.2 integration install 后文件为空？
    检查模板文件是否真的有内容：`Get-Content .\integrations\<id>\files\...tpl | Select-Object -First 5`
    检查变量字典是否齐全：integrations_service.collect_values(cfg) 返回的 dict

B.3 doctor 里 integrations 检查项名空了？
    discover_integrations 要扫的是 workbench_root/integrations/*/manifest.yaml
    确认 cfg["agent_workbench_root_path"] 是正确的 Path

B.4 Path traversal 检测失败？
    install_integration 里：
      target = (project_root / dst).resolve()
      if not str(target).startswith(str(project_root.resolve())):
          raise RuntimeError(...)

B.5 迁移文件后发现目标缺失
    在 PowerShell 里用 `Test-Path <dst>` 验证；用 `Get-Content <dst> | Select-Object -First 5`
    看内容。如果源文件还在，回头执行一次 Move-Item 即可。

11. 附录 C：FAQ
================================================================================

Q1: 新增一个集成（比如 cursor）要改多少代码？
A1: 0 行。只需要加目录 agent_workbench/integrations/cursor/
    manifest.yaml + files/*.tpl，重跑 doctor 就会自动扫描到。

Q2: 用户不想装任何 AI 前端怎么办？
A2: 允许。agent_workbench 核心命令（doctor/build/flash/uart/plan 等）独立工作，
    integrations/ 是 opt-in 的。doctor 的 _check_integrations 遇到空就默不出声。

Q3: 两个集成有冲突文件（都要写 AGENTS.md）怎么办？
A3: install_integration 后写者覆盖前写者。用户显式 install 两个冲突集成是
    他自己的选择，workbench 给 warn 但不阻止。未来可加 --merge 策略。

Q4: 模板里怎么用条件逻辑？
A4: 本版本 manifest 只支持 {key} 替换。如果需要条件，在 integrations/<id>/
    内部再做个小 python script（作为自由扩展），workbench 不管。

Q5: 集成包能 include 其他集成包的文件吗？
A5: 本版本不支持。保持简单。未来可加 manifest.depends_on 字段。

12. 附录 D：失败应对
================================================================================

如果任何阶段失败:

 - 不要尝试 git 操作；由用户自己决定是否 reset / checkout / restore。
 - 执行方（AI）只需：
     a) 停止后续阶段
     b) 给用户完整汇报：失败原因 + 已改动的文件列表 + 建议的恢复方向
     c) 等待用户人工决定
 - 可以用 read_file 展示每个被修改文件的当前状态，让用户对比。
 - 绝不自动"回退"或"撤销"——这是用户的职责。
